# Threshold PSI Circuit (TPSI)

Threshold PSI Circuit is a Python prototype for studying threshold private set intersection using Bloom filters and a boolean threshold circuit, with an encrypted evaluation path built on OpenFHE threshold BFV.

Instead of asking whether an item appears in every party's set, this project asks a more general question: does an item appear in at least `T` out of `N` party datasets?

## What this project does

- Generates or reloads synthetic party datasets of IPv4 addresses.
- Encodes each party's dataset into a Bloom filter.
- Builds a threshold circuit for `T-of-N` membership.
- Evaluates that circuit in plaintext for validation and benchmarking.
- Evaluates the same circuit with OpenFHE threshold BFV, one Bloom-filter bit at a time.
- Uses a joint public key and collaborative decryption shares so no single party can decrypt alone.
- Recovers candidate elements from the resulting threshold-intersection Bloom filter.
- Produces scaling plots for parties, threshold, party-set size, and number of common IPs.

## Why this is useful

This repository is useful if you want to explore the tradeoff between:

- probabilistic set encoding with Bloom filters,
- threshold-style set intersection,
- and the computational cost of homomorphic evaluation.

It is best understood as a research or demonstration codebase, not a production PSI implementation.

## Repository layout

- `Circuit.py`: original Concrete/single-key prototype.
- `Circuit_OpenFHE.py`: OpenFHE threshold BFV implementation with multiparty key generation and collaborative decryption.
- `Circuit_TPSI.py`: earlier unified implementation with interactive menu and standalone script modes.
- `party_sets/`: cached/generated input datasets used by the demo (organized by parameter configurations).
- `Final_Results/`: generated plots, pivot tables, and comparison outputs used for final analysis.
- `benchmark_outputs/`: legacy plots and results generated by earlier scaling experiments.
- `requirements.txt`: Python package dependencies.

## How the workflow works

1. Generate `N` party datasets.
2. Seed selected IP addresses into exactly `T` parties.
3. Fill the rest of each party dataset with unique random IPv4 addresses.
4. Build one Bloom filter per party.
5. Construct the canonical threshold circuit and reduce it to a compact positive-literal SOP form.
6. Evaluate the circuit over Bloom-filter bits.
7. Reconstruct a Bloom filter from the result and test candidate items from the union of all party sets.
8. Compare the recovered candidates against the exact threshold intersection.

## Requirements

- Python 3.10 or newer is recommended.
- `numpy`
- `pyprobables`
- `matplotlib`
- `openfhe` Python wrapper for the threshold BFV encrypted evaluation path

Install dependencies with:

```bash
pip install -r requirements.txt
```

The OpenFHE Python wrapper is distributed as platform-specific wheels. Ubuntu 22.04 and 24.04 are the intended targets for the pip package. If installation through `requirements.txt` does not match your environment, install the wheel recommended by the OpenFHE Python project for your OS/Python version.

## Quick start

Run the OpenFHE implementation from the project root:

```bash
python Circuit_OpenFHE.py -c n3_t2_c5_s10
```

The `-c` option selects a cached/generated dataset configuration in the form:

```text
n<num_parties>_t<threshold>_c<num_common_ips>_s<party_set_size>
```

Useful commands:

```bash
python Circuit_OpenFHE.py --generate-input
python Circuit_OpenFHE.py --verify-input
python Circuit_OpenFHE.py -c n3_t2_c5_s10
```

Runtime logs are written under `benchmark_outputs/`.

### Legacy Interactive Menu

The older interactive script is still available:

```bash
python Circuit_TPSI.py
```

This launches an interactive menu with options to:
1. **Generate input files** - Prepare datasets for multiple experiment configurations
2. **Run sample experiment** - Execute a single experiment with user-selected parameters
3. **Run scaling experiments** - Run one or more scaling sweeps and save plots

Menu options allow you to select specific experiments:
- Run all 4 scaling sweeps simultaneously
- Run only parties scalability test
- Run only threshold scalability test
- Run only party set size scalability test
- Run only common IPs count scalability test

## Configuration

Configuration options can be customized in two ways:

### Via the Interactive Menu
When using interactive menu mode, you can select parameters at runtime for each experiment.

### Via Configuration File
After running the program once, a configuration file is created at:
```
party_sets/party_sets_meta.json
```

You can edit this file to adjust default values for future runs or modify the scaling sweep parameters.

Key parameters:
- `num_parties`: number of participating datasets (N)
- `threshold`: minimum number of parties that must share an item (T); this is the PSI threshold, not the threshold FHE decryption threshold.
- `false_positive_rate`: Bloom-filter false positive rate (1 / party_set_size)
- `num_common_ips`: number of seeded IPs shared by exactly `threshold` parties
- `party_set_size`: number of IPs in each party dataset

## Output & Results

The program generates:
- **Scaling plots** in `benchmark_outputs/` showing:
  - Computation time vs. number of parties
  - Computation time vs. threshold value
  - Computation time vs. party set size
  - Computation time vs. number of common IPs
  - Encrypted timing breakdowns for preprocessing, encryption, evaluation, and decryption
- **Party datasets** in `party_sets/` organized by parameter configuration (e.g., `n3_t2_c5_s100/`)
- **Configuration metadata** in `party_sets/party_sets_meta.json`

The final-result plots and pivot table summaries live in `Final_Results/`. That directory is kept in git for the PNG outputs, while runtime logs and `graph.py` are ignored locally.

Only `party_sets/party_sets_meta.json` is kept in git under `party_sets/`; the generated per-configuration text files remain local-only.

## Notes on correctness and interpretation

- The exact threshold intersection is computed directly from the plaintext party sets for comparison.
- Bloom filters are probabilistic, so the recovered candidate set can include false positives.
- The OpenFHE encrypted evaluation processes one Bloom-filter position at a time, which is useful for demonstration but can be expensive for large configurations.
- The implementation uses OpenFHE threshold BFV with a joint public key, public evaluation keys, per-party secret-key shares, and collaborative decryption.
- The PSI threshold `T` controls the set-intersection condition. The current threshold FHE decryption flow uses all generated party key shares for collaborative decryption.
- Benchmark measurements are based on actual sampled Bloom-filter bits. Full-size estimates are computed via linear scaling.

## Limitations

- This is a research prototype, not a production PSI deployment.
- Party datasets are synthetic and randomly generated.
- The encrypted path depends on a local OpenFHE Python installation and may not work on every system.
- The implementation prioritizes clarity and experimentation over protocol hardness, networked execution, and production performance.

## Troubleshooting

### OpenFHE import or initialization errors
`Circuit_OpenFHE.py` imports OpenFHE at module load time. If `from openfhe import *` fails, install the OpenFHE Python wrapper for your platform before running the encrypted workflow.

### Per-bit progress logs
Per-bit progress logs are disabled by default. To enable them, set:

```bash
export TPSI_FHE_PROGRESS_EVERY=100
```

### Old party_sets directories
If you have old `party_sets_bloom/` or `party_sets_menu/` directories from previous versions, you can safely delete them. Circuit_TPSI.py uses a unified `party_sets/` directory.
