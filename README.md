# Threshold PSI Circuit

Threshold PSI Circuit is a Python prototype for studying threshold private set intersection using Bloom filters and a boolean threshold circuit, with an optional encrypted evaluation path built on Concrete FHE.

Instead of asking whether an item appears in every party's set, this project asks a more general question: does an item appear in at least `T` out of `N` party datasets?

## What this project does

- Generates or reloads synthetic party datasets of IPv4 addresses.
- Encodes each party's dataset into a Bloom filter.
- Builds a threshold circuit for `T-of-N` membership.
- Evaluates that circuit in plaintext for validation and benchmarking.
- Optionally evaluates the same circuit with Concrete FHE, one Bloom-filter bit at a time.
- Recovers candidate elements from the resulting threshold-intersection Bloom filter.
- Produces scaling plots for parties, threshold, party-set size, and number of common IPs.

## Why this is useful

This repository is useful if you want to explore the tradeoff between:

- probabilistic set encoding with Bloom filters,
- threshold-style set intersection,
- and the computational cost of homomorphic evaluation.

It is best understood as a research or demonstration codebase, not a production PSI implementation.

## Repository layout

- `bloom.py`: main implementation, demo entry point, and benchmarking code.
- `party_sets/`: cached/generated input datasets used by the demo.
- `benchmark_outputs/`: example plots generated by the scaling experiments.

## How the workflow works

1. Generate `N` party datasets.
2. Seed selected IP addresses into exactly `T` parties.
3. Fill the rest of each party dataset with unique random IPv4 addresses.
4. Build one Bloom filter per party.
5. Construct the canonical threshold circuit and reduce it to a compact positive-literal SOP form.
6. Evaluate the circuit over Bloom-filter bits.
7. Reconstruct a Bloom filter from the result and test candidate items from the union of all party sets.
8. Compare the recovered candidates against the exact threshold intersection.

## Requirements

- Python 3.10 or newer is recommended.
- `numpy`
- `pyprobables`
- `matplotlib`
- `concrete-python` for the encrypted evaluation path

Install dependencies with:

```bash
pip install -r requirements.txt
```

If `concrete-python` is not available or fails to initialize on your machine, the script still runs the plaintext workflow and reports that the encrypted path is unavailable.

## Quick start

Run the demo from the project root:

```bash
python bloom.py
```

The default demo parameters in `bloom.py` are:

- `NUM_PARTIES = 3`
- `THRESHOLD = 2`
- `FALSE_POSITIVE_RATE = 0.0005`
- `NUM_COMMON_IPS = 1`
- `PARTY_SET_SIZE = 5`

The script will:

- load or generate party datasets,
- print Bloom-filter parameters,
- evaluate the threshold circuit in plaintext,
- attempt encrypted evaluation,
- and run scaling experiments that save plots into `benchmark_outputs/`.

## Example outputs

The repository includes example benchmark plots in `benchmark_outputs/`.

Current committed examples include:

- computation time vs. number of parties,
- computation time vs. threshold,
- computation time vs. party-set size.

The code can also generate a plot for computation time vs. number of common IPs.

## Configuration

The main parameters are defined near the bottom of `bloom.py`:

- `NUM_PARTIES`: number of participating datasets.
- `THRESHOLD`: minimum number of parties that must share an item.
- `FALSE_POSITIVE_RATE`: Bloom-filter false positive rate.
- `NUM_COMMON_IPS`: number of seeded IPs shared by exactly `THRESHOLD` parties.
- `PARTY_SET_SIZE`: number of IPs in each party dataset.
- `RUN_SCALING_EXPERIMENTS`: enables benchmark plot generation.

## Notes on correctness and interpretation

- The exact threshold intersection is computed directly from the plaintext party sets for comparison.
- Bloom filters are probabilistic, so the recovered candidate set can include false positives.
- The encrypted evaluation currently runs one bit position at a time, which is useful for demonstration but expensive for large configurations.
- Benchmark extrapolation is based on sampled Bloom-filter bits because full encrypted evaluation becomes very costly at scale.

## Limitations

- This is not a full secure multi-party PSI protocol.
- Party datasets are synthetic and randomly generated.
- The encrypted path depends on the local Concrete FHE environment and may not work out of the box on every system.
- The implementation prioritizes clarity and experimentation over protocol hardness, networked execution, and production performance.
